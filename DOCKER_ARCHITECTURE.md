# Docker Architecture

Everything runs in Docker Compose on one bridge network, `flead_network`.
Services reach each other by container name (`kafka-broker-1:9092`,
`timescaledb:5432`, …). `START.bat` / `./start` build and start the stack;
`STOP.bat` / `./stop` remove the project's containers and keep the volumes.

## Services

| Service | Image / Dockerfile | Host port | Role |
| --- | --- | --- | --- |
| `kafka-broker-1` | `confluentinc/cp-kafka:7.6.1` (KRaft, no ZooKeeper) | 9092 | The single broker |
| `kafka-producer` | `Dockerfile.producer` (python:3.10-slim, kafka-python only) | – | Streams the 2,400 device CSVs at 150 readings/s |
| `flink-jobmanager` | `Dockerfile.flink` (flink:1.18-java11 + PyFlink) | 8161 (UI), 6123 | Runs the PyFlink job: RRCF scoring and local training |
| `flink-taskmanager` | `Dockerfile.flink` | – | 2 task slots, parallelism 2, 1 GB process memory |
| `federated-aggregator` | `Dockerfile.aggregator` (python:3.10-slim) | – | FedAvg rounds, DP-FedAvg, model registry, rollback, update clustering |
| `spark-master` | `Dockerfile.spark` (apache/spark:3.5.0) | 8086 (UI), 4040 (job UI), 7077 | Runs `05_spark_analytics.py` (stream windows, batch stats, held-out evaluation) |
| `spark-worker-1` | `Dockerfile.spark` | 8087 (UI) | Spark executor |
| `timescaledb` | `timescale/timescaledb:2.15.1-pg14` | 5432 | Time-series storage |
| `database-init` | `Dockerfile.database-init` (python:3.10-slim) | – | Creates the tables and hypertables, then exits |
| `timescaledb-collector` | `Dockerfile.timescaledb-collector` (python:3.10-slim) | – | Writes readings, anomalies and model updates from Kafka to TimescaleDB |
| `dashboard-metrics-updater` | `Dockerfile.aggregator` image | – | Writes fleet KPI snapshots to `dashboard_metrics` every 15 s |
| `grafana` | `grafana/grafana:11.0.0` | 3001 | 5 provisioned dashboards (Overview, Federated Learning & Privacy, Anomalies, Devices, Operations), generated by `grafana/build_dashboards.py`; TimescaleDB and Prometheus data sources |
| `grafana-init` | `Dockerfile.grafana-init` (python:3.10-slim) | – | Checks the data source and removes a legacy dashboard, then exits |
| `prometheus` | `prom/prometheus:v2.47.0` | 9090 | Scrapes Flink, Spark and the pipeline metrics; evaluates 16 alert rules |
| `alertmanager` | `prom/alertmanager:v0.26.0` | 9093 | Routes alerts to the monitoring dashboard webhook |

| `kafka-ui` | `provectuslabs/kafka-ui:latest` | 8081 | Inspect topics and consumer groups |
| `jupyter-dev` | `Dockerfile.jupyter-dev` (python:3.11-slim) | 8888 | Notebooks |
| `data-preprocessor` | `Dockerfile.data-preprocessor` (python:3.11-slim), profile `data` | – | Downloads Edge-IIoTset from Kaggle and builds the device CSVs; run only when `data/processed` is empty |

## Data flow

```text
data/processed/device_N.csv
      │ kafka-producer
      ▼
Kafka: edge-iiot-stream ─────────────► timescaledb-collector ─► TimescaleDB ─► Grafana
      │                                        ▲
      ├─► Flink job ─► anomalies ──────────────┤
      │            └─► local-model-updates ─┬──┘
      │                                     ▼
      │                        federated-aggregator ─► global-model-updates
      │                                     │
      │                     models_global volume (global_model_latest.json)
      │                          │ read by Flink (next local round) and Spark
      └─► Spark (spark-master) ──┴─► stream windows, held-out evaluation ─► TimescaleDB
```

Kafka topics: `edge-iiot-stream`, `local-model-updates`, `global-model-updates`,
`anomalies`, `system-alerts` (replication factor 1, 4 partitions). The
orchestrator creates missing topics. If the producer or aggregator publishes
first, the broker auto-creates the topic with the same 4 partitions
(`KAFKA_NUM_PARTITIONS`). An existing topic keeps its partition count; see
[docs/KAFKA_SINGLE_BROKER.md](docs/KAFKA_SINGLE_BROKER.md#topics).

## Startup order

Compose starts services in dependency order:

| Service | Waits for |
| --- | --- |
| `database-init` | `timescaledb` healthy |
| `timescaledb-collector` | `timescaledb` healthy, `database-init` finished, `kafka-broker-1` started |
| `federated-aggregator` | `kafka-broker-1` started, `timescaledb` healthy, `database-init` finished |
| `dashboard-metrics-updater` | `timescaledb` healthy, `database-init` finished, `federated-aggregator` started |
| `flink-jobmanager` / `flink-taskmanager` | `kafka-broker-1` started / `flink-jobmanager` started |
| `spark-master` / `spark-worker-1` | `kafka-broker-1` started and `timescaledb` healthy / `spark-master` healthy |
| `kafka-producer`, `kafka-ui` | `kafka-broker-1` started |
| `grafana`, `device-viewer` | `timescaledb` healthy |
| `grafana-init` | `grafana` started, `database-init` finished |
| `monitoring-dashboard` | `timescaledb` healthy, `kafka-broker-1` started |

The producer and the collector retry their Kafka connection while the broker
finishes starting. `scripts/pipeline_orchestrator.py` then waits for the
containers, creates the topics, submits the Flink job (`flink run`) and the
Spark job (`spark-submit` in `spark-master`), and opens the web UIs.

## Storage

Named volumes (kept by `STOP.bat` / `./stop`):

| Volume | Used by |
| --- | --- |
| `kafka_broker_1_data` | Kafka log |
| `timescaledb_data` | TimescaleDB |
| `models_global` | Written by `federated-aggregator`, mounted read-only into the Flink TaskManager |
| `grafana_data`, `prometheus_data` | Grafana state, Prometheus TSDB |
| `flink_jobmanager_data`, `flink_taskmanager_data`, `spark_master_data`, `spark_worker_data` | Flink and Spark working state |

Bind mounts from the repository: `./scripts` (read by the Python services,
Flink and Spark), `./data` (device CSVs), `./grafana/dashboards` and
`./grafana/provisioning`, `./prometheus`, and `./kaggle` (Kaggle API token for
the preprocessor and Jupyter; never committed).

## Configuration

Credentials and the train/held-out split come from environment variables with
local defaults; copy `.env.example` to `.env` to change them:
`POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `GRAFANA_ADMIN_USER`,
`GRAFANA_ADMIN_PASSWORD`, `STREAM_ROWS_PER_DEVICE`. Model settings are listed
in [scripts/README.md](scripts/README.md#configuration).

## Monitoring

Prometheus scrapes:

- `monitoring-dashboard:5000/metrics`: pipeline metrics from TimescaleDB, such as held-out accuracy and F1, anomaly rate, DP ε and device counts;
- `flink-jobmanager:9249` and `flink-taskmanager:9249`: Flink's Prometheus reporter;
- `spark-master`: Spark's Prometheus servlet.

The alert rules live in `prometheus/alerts.yml`. They cover model quality, privacy budget, anomaly rate, stale devices, the database, scrape targets, Flink restarts and heap, and lost Spark workers.

## Commands

```bash
docker compose ps                          # container status
docker compose logs -f federated-aggregator
docker compose --profile data down         # what STOP.bat / ./stop run (volumes kept)
docker compose down -v                     # also delete all volumes (full reset)
```
